# 命令行陪跑（我自己敲模式）

**触发场景**：用户要办成一件真实的事（推 GitHub、装环境、跑项目、改配置…），但明确说「我想自己敲/别帮我跑/把命令给我」。此时**不要用工具替他执行**，只给可复制的命令 + 逐词讲解，他在自己终端敲。

**为什么单独成 skill**：这不是 `/learn`（目的是系统学习）。这里的目标是**把事办成**，同时让用户亲手完成关键操作。因此节奏更快、更任务导向，但每条命令仍要讲透。

## 铁律：每条命令都逐词解释

不能只写"这行干嘛"，要写清**字面本身**：

- **命令是什么单词的缩写**：`mkdir`=make directory 新建文件夹；`cp`=copy 复制；`cd`=change directory 切目录；`ls`=list 列出；`rm`=remove 删除；`mv`=move 移动/改名；`git`=版本管理；`gh`=GitHub 命令行工具；`brew`=Homebrew 软件包管理器。
- **每个 `-参数`/`--选项` 什么意思**：`-p`=parents 上级不存在就一起建；`-R`/`-r`=recursive 连子文件夹一起；`-la`=long+all 详细+含隐藏；`-m`=message 存档说明；`--private`=私密；`--push`=建好立刻上传；`-f`=force 强制（危险，用前必警告）。
- **符号**：`NEW=...` 定义变量（`=` 左右不能有空格）；`$NEW` 取变量值；`"..."` 双引号把里面当整体（路径含中文/空格必加）；`~` 代表当前用户的主目录；`.` 代表当前文件夹；`/.` 表示“文件夹里面的内容”；`#` 是注释；`|` 是管道；`>` 是输出重定向。

即使是讲过的基础命令，也顺带简短复述含义，帮助用户通过重复建立记忆。

## 陪跑节奏

1. **动手前先说清**：这条命令中文直译、每个词含义、会不会改本地文件或远端、成功后预期看到什么，再给可敲的代码。
2. **一行一块**：把命令拆成一小段一小段（复杂命令一条一个代码块），叮嘱他「一行一行粘，没红字再敲下一行」。
3. **预告成功信号**：明确说"跑对了应该看到 XXX"（如 `✓ Pushed`、`2 files changed`），他好自己判断。
4. **报错就诊断**：他把终端输出贴回来后，**先定位是哪一行、错在哪个字面**，讲清原因（让他学到），再给修正版——下一步仍是他来敲。

## 小白高频坑（主动预警）

- **含空格或非 ASCII 字符的路径优先用完整绝对路径**：`~` 后面必须紧跟 `/`（`~Downloads` 会被当成用户名）；而且 `~` 被双引号包住后不会展开。需要可移植写法时使用 `"$HOME/..."`。
- **`变量=值` 等号两边不能有空格**。
- **引号要配对**：终端出现 `dquote>` 就是引号少了一半，按 `Ctrl+C` 取消重来。
- **中文/空格路径必须加双引号**，否则被拆断。
- 🔴 **危险命令**（`rm -rf`、`git reset --hard`、`git push -f`、`--force`）：给之前必须**单独一条消息**讲清后果、等他确认无误，再给可敲的命令。不确认不给。

## 红线沿用

- 除非用户明确要求，不在 commit 中添加 AI 署名或生成标记。
- 终端里出现的 API key/token，写进任何文档或 repo 前替换成 `sk-***`。
- 新建 repo 默认 `--private`。

## 边界

- 用户没说"自己敲"、而是"全包/直接做"时，不走本模式，直接用工具执行。
- 目的是“学会某个技术概念”而非“办成一件事”时，走 `/learn`（讲一段停一段、检查理解、写学习记录），不是本 skill。
