# 会议表现复盘

复盘的对象是用户在会议中的表达、判断和推进动作，不是会议内容本身。所有评价必须有原话或用户自述作为依据。

## 输入

- 本次会议的整理稿，重点定位用户的发言原文；
- 用户对紧张点、卡壳点和目标的自述；
- 若存在，读取过去的会议复盘和上次改进项；
- 会议对象的角色和决策权限；不根据姓名猜测风格或立场。

## 复盘框架

1. **表现事实**：分别引用有效表达和需要改进的具体实例，避免空泛表扬。
2. **对照上次行动**：逐条判定“做到 / 未做到 / 本次没有机会使用”。
3. **表达技法拆解**：检查是否结论先行、结构清楚、证据充分、请求明确；为关键原话给出更清晰的重说版本。
4. **推进效果**：判断会议结束时是否形成决策、负责人、验收标准和下一步。
5. **下次准备**：最多给 3 条可执行动作，并预写 1–2 个反问和 1 个具体例子。

## 按沟通对象调整

- **决策者**：先给结论、选项、风险和推荐，请对方拍板。
- **技术导师或专家**：带着已验证事实、假设和具体问题，请对方校准方案。
- **协作同事**：对齐责任边界、交付物、依赖和时间。
- **客户或外部伙伴**：确认需求、验收标准、授权范围和下一步书面记录。

只有当材料中存在证据时才判断对方偏好；不要使用固定人物画像替代本次会议事实。

## 落盘

优先续写用户指定或仓库已有的会议复盘文档；若没有约定，建议保存到 `meetings/reviews/`，按日期新建文件。不得覆盖历史复盘。

## 边界

- 不编造用户没说过的话，不把 AI 改写当作用户原话。
- 不根据性别、职位或私人关系做心理推断。
- 私人身份、公司内部事件和无关敏感信息只在完成复盘所必需时保留，并遵循用户的匿名化要求。
- 先指出证据不足，再给建议；不要用确定语气包装猜测。
