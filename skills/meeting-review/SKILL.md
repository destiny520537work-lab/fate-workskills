# 会议表现复盘（提升表达）

目的不是复盘会议内容（那是 `meeting-notes` 的任务），而是复盘**用户这个人的临场表现**，让表达力可以逐次迭代。

## 输入

- 本次会议的 `_整理.md`，用来定位用户的发言原文；
- 用户在对话里的自述，例如紧张点、卡壳点和原本目标；
- 若存在，读取历史复盘和上次立下的改进项；
- 若存在，读取用户已验证过的学习对象画像；公开版只使用“技术导师 A”“业务负责人 B”等角色，不保留真实姓名、公司或内部路径。

## 复盘框架

1. **表现事实**：引用用户的具体发言或行为，好的和需要改进的都要有实例，不许空泛表扬；
2. **对照上次改进项**：逐条判定“做到 / 没做到 / 本次没机会使用”；
3. **表达技法拆解**：检查是否结论先行、是否使用三段式或阶段结构、是否有数字和实例支撑；指出关键原话如果重说应该怎么说，并给出改写；
4. **推进效果**：会议结束时是否形成决策、负责人、验收标准和下一步；
5. **下次会议准备**：最多 3 条可执行动作，预写 1–2 个反问和 1 个具体例子。

## 两类典型沟通对象（策略不同）

- **技术导师 A**：对方要的是确认和推进。带着已验证事实和方案去，给出 2–3 个选项、明确推荐，再请对方校准或拍板；
- **业务负责人 B**：对方要的是结构和结论先行。先讲结果与影响，再讲三点依据，最后提出明确请求，不要先铺大量过程细节。

这些是脱敏后的沟通原型，不是对真实人物的固定心理画像。只有会议证据与该特征一致时才使用；否则按本次事实重新建模。

## 脱敏示例

**原话：**

> 我这周看了一些东西，然后中间有几个地方不是特别确定，可能还要再试试，所以想问一下后面是不是可以继续这样做。

**问题：** 没有先说结论；“一些东西”“几个地方”“这样做”都缺少指代；对方不知道需要做什么决定。

**重说：**

> 结论是方案 A 可以继续，但数据校验还差一步。我已经完成两项检查，剩下的问题是样本 C 是否纳入。我的建议是先按方案 A 推进，本周补完校验；请您确认样本 C 的处理口径。

**可提前准备的反问：**

1. 您判断这一步完成的验收标准是什么？
2. 如果方案 A 与当前优先级冲突，您更希望我先保留哪一部分？

示例使用虚构的方案和样本编号，只保留“原话证据 → 问题 → 重说 → 反问”的训练结构。

## 落盘

优先续写用户指定或仓库已有的会议复盘文档，按日期为本次会议增加一个新小节，而不是每次另建一套孤立文档。若没有现成复盘文件，再在 `meetings/reviews/` 新建。长期的沟通对象观察单独保存，并标记证据日期。不得覆盖历史复盘。

## 红线

- 只基于整理稿和用户自述评价，不编造用户没说过的话；
- 不把 AI 的改写当作用户原话；
- 不根据性别、职位或私人关系做心理推断；
- 未经授权公开的重大人事、法律、客户、财务与安全事件不得出现在对外复盘中，也不得留下可反推出事件性质的暗示；
- 公司内部事件、真实姓名和无关隐私在公开范例中统一改为虚构角色、项目和数据；
- 证据不足时先写“无法判断”，再给可验证的建议。
