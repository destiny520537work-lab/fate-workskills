# 每日进展回顾

这个流程从对话记录和文件证据中恢复工作线索，帮助用户在任务切换后准确接续。

## 流程

1. **抓记录**：运行 [scripts/extract-day.sh](scripts/extract-day.sh)，依次传入本地日期、转录根目录和 IANA 时区：
   ```bash
   bash skills/daily/scripts/extract-day.sh 2026-07-08 "$HOME/.claude/projects" Asia/Shanghai
   ```
   输出该天所有会话里用户的发言（已按时间排序、剥离系统标签）。
2. **交叉核对**：对照 `git log --since` 当天提交、当天新增/修改的文件，判断哪些事真做完了。
3. **三栏归类**，各条注明出处（哪个会话/文件）：
   - ✅ 已完成 — 有产出文件或已推送为证
   - ⏸ 做到一半 — 写明卡在哪一步、下一步动作是什么（这栏最重要，是防忘的核心）
   - ⬜ 待做 — 当天提过但没动的
4. **落盘**：优先使用用户指定的进展文件；若未指定，先查找仓库现有 daily/progress 文档，再建议 `docs/daily-progress.md`。格式为 `## YYYY.M.D`，新日期放在文件顶部，不覆盖已有日期。
5. **口头汇报**：对话里只报「做到一半」和「待做」里最要紧的 3 件，别复述全文。

## 周清单模式

用户贴出周 todo list 时：逐条对照对话记录和文件产出，标出“以为没做其实做了 / 以为做了其实没做 / 完全遗漏”三类，再提醒能够从证据确认的临近截止日期。

## 注意

- Claude Code 对话通常位于 `~/.claude/projects/`，具体子目录因机器和项目而异。时间戳是 UTC；脚本依据传入时区换算日期窗口，不要手动按 UTC 日期筛选。
- 记录可能包含私人生活、凭据或公司信息。只保留与工作接续直接相关的事实；密钥、token、住址、支付信息和无关隐私一律不写入进展文档。
