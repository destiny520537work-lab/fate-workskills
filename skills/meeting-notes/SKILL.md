# 会议录音整理（两件套）

## 目录约定

- **输入**：用户指定的原始听写文件。若没有现成目录，可使用 `meetings/raw/`；
- **输出**：优先沿用仓库约定，否则使用 `meetings/notes/`，生成两个新文件：
  - `<会议名>_整理.md`：全文整理版；
  - `<会议名>_总结.md`：三分钟可回看的总结版；
- **铁律**：原始文件永不改动；已存在的输出不覆盖，发现同名文件时必须先询问用户。

## 执行方式

原始文件达到 **3KB 或以上**且运行环境支持子 agent 时，“整理全文”和“提炼总结”必须各开一个独立 reviewer 并行处理；两个任务都必须收到下方规则、隐私红线和存疑要求。文件小于 3KB 时可以由主 agent 直接完成。若运行环境不支持子 agent，明确说明限制并用两个隔离步骤代替，不能静默省略独立复核。

## 输入变体：结构化 AI 会议纪要

若用户提供的是已经包含“总结 / 待办 / 相关链接”等栏目的 AI 纪要，不重复制作全文整理版：

1. 原文归档到原始材料目录，不改写；
2. 只输出 `_总结.md`：核心结论 + 与用户直接相关的待办；每项待办注明谁派发、交给谁审核、负责人和截止时间，并把调研任务拆成可直接开工的问题清单；
3. AI 纪要可能不准确，关键数字、责任人、截止时间和承诺仍需回到原始证据核查；无法核查时标记“待确认”。

## 整理版规则

1. 保留全部内容和口语原意，不擅自缩写、摘要、删去“看似无关”的内容或新增观点；
2. 只修复有充分上下文依据的同音和近音错字；没把握时使用 `（存疑：原文“……”）`，**人名和数字绝不猜改**；
3. 加标点、按话题分段；能分辨说话人时使用“**负责人 A：**”“**用户：**”等一致角色标签；
4. 每个大话题增加 `## 小标题`，方便跳读；
5. 文件开头说明“本文为听写文本整理版”，并链接或注明原始记录位置。

## 总结版规则

1. 结构：一句话概览 → 会议基本信息 → 核心内容分主题 → 与用户直接相关的行动项 → 转写存疑处；
2. 使用短句和列表，控制在三分钟内能看完；模板或汇报字段尽量还原原始规则；
3. 数字、人名、日期和承诺只使用材料里出现的内容，宁可标存疑也不自行补全；
4. 行动项使用表格：事项｜派发人｜负责人｜审核人｜验收标准｜截止时间｜证据原句。缺失字段写“未明确”。

## 隐私红线

- 主动识别未经授权公开的重大人事、法律、客户、财务与安全事件，不依赖用户逐段标记；这类段落在整理版使用 `（此段已按要求隐藏）`，总结版直接省略，公开产物不得留下能反推出事件性质的暗示；
- 用户另行标记为公司机密、客户隐私或私人信息的段落，按同一规则处理；
- 匿名化时使用一致角色标签，例如“负责人 A”“客户 B”“项目 C”；匿名映射不得写入公开产物；
- 不要留下能通过部门名、客户名、内部系统名、精确业务数字或固定路径反推出真实主体的组合线索；
- 不把原始转写或内部材料上传到外部服务，除非用户明确授权。

## 常见听写错字示例

| 听写原文 | 结合上下文后可能是 |
| --- | --- |
| 试什么 / 外为什么 | WHAT / WHY |
| 事物性工作 | 事务性工作 |
| 勾集 | 勾稽 |
| 宙斯（场） | 周四（场） |
| KPR | KPI |
| 与众为始 | 以终为始 |
| 复构 | 复购 |

这张表只是校对提示，不是自动替换字典。新出现的高频错字只有在多处上下文确认后才可加入；人名永远保留原文并标存疑。

## 脱敏示例

```text
原始转写：负责人说项目c下周四以前先给一个初稿然后客户那边谁看还没定

整理版：
**负责人 A：** 项目 C 下周四以前先提供一版初稿；客户侧审核人尚未确定。

行动项：
| 事项 | 派发人 | 负责人 | 审核人 | 验收标准 | 截止时间 | 证据原句 |
| --- | --- | --- | --- | --- | --- | --- |
| 提供项目 C 初稿 | 负责人 A | 未明确 | 未明确 | 一版可供审核的初稿 | 下周四以前（具体日期存疑） | “下周四以前先给一个初稿” |
```

示例保留了“不能补负责人、具体日期和客户姓名”的判断动作，但没有使用任何真实公司或项目资料。

## 完成后

在对话里报告两个文件路径、各自内容要点、行动项数量和存疑数量，提醒用户优先检查人名、数字、日期和承诺。
